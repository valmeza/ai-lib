name: test-plan
description: Create a test plan from the implementation and acceptance criteria.
---

When creating a test plan:

1. **Read `tasks.md`** — review the acceptance criteria for each task.
2. **Read the implementation** — understand what changed and how.
3. **Identify test scenarios**:
   - Happy path — does the feature work as expected?
   - Edge cases — empty state, errors, boundaries, unusual input
   - Regression — does existing behavior still work?
   - Integration — do the changes work with the rest of the system?
4. **Document the test plan** — list what will be tested and how.

Output a structured test plan ready for execution.
