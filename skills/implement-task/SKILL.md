---

When implementing a task:

1. **Read the task** from `tasks.md` — understand what needs to be built, the acceptance criteria, and any dependencies.
2. **Explore the codebase** — find the relevant files, understand existing patterns and conventions.
3. **Plan the implementation** — think through the approach before writing code.
4. **Write code** following these rules:
   - Match the existing code style (naming, imports, structure)
   - Use existing libraries/frameworks already in the project
   - Don't add comments unless the project convention uses them
   - Keep changes minimal and focused on the task
5. **Verify** — run the relevant tests and lint checks.
6. **Commit** with a clear, conventional commit message.
7. **Mark the task complete** in `tasks.md` by checking the box or updating status.
